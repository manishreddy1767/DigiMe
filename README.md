# Digital Me

A private, local-first AI digital human. It combines text chat with a local
Ollama model and keeps conversation history only in the current browser session.

## What works

- React/Three.js VRM viewer and text chat UI.
- FastAPI chat endpoint backed by Ollama's local `/api/chat` endpoint.
- Qwen3 4B with a 4K-token context; sent history is bounded to the latest 20
  messages and 12,000 characters, including the system prompt.
- New-conversation, loading and error states.
- VRM idle motion and blinking, with thinking and brief speaking expressions
  driven by chat activity. The avatar supports a happy expression, but chat does
  not infer or select emotions automatically.
- On-demand Kokoro text-to-speech runs locally on the CPU. Audio is held
  temporarily in browser memory and is not saved by the backend.
- The speaking expression follows actual audio playback, but is not synchronized
  to speech sounds or phonemes.
- No cloud APIs, microphone, speech recognition, database, or permanent memory.

## Prerequisites

- Python 3.11+ and Node.js/npm.
- Ollama running locally.
- A compatible VRM 1.0 file at `frontend\public\models\avatar.vrm` to display
  the avatar. Model files are local-only and ignored by Git.

To supply an avatar, use a VRM 1.0 model you have permission to use, then copy
it to the expected path from the repository root:

```powershell
New-Item -ItemType Directory -Force frontend\public\models
Copy-Item "$env:USERPROFILE\Downloads\your-avatar.vrm" frontend\public\models\avatar.vrm
```

The model must include VRM 1.0 metadata. The existing viewer keeps its
missing-model fallback until a compatible file is present; no avatar model is
included or generated by this project.

## Install

In PowerShell:

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[test,tts]"
ollama pull qwen3:4b
```

In another terminal:

```powershell
cd frontend
npm ci
```

Ollama model downloads happen locally. Chat requests go only to Ollama at
`127.0.0.1:11434`; the backend and Vite development server bind to loopback.
Kokoro inference is local and CPU-only. On first TTS use, Kokoro may download
its model and voice weights into the local Hugging Face cache; no conversation
text is sent to that model host. Later synthesis uses the cached weights.

## Run the app

Start the backend from `backend`:

```powershell
.\.venv\Scripts\Activate.ps1
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Start the frontend from `frontend`:

```powershell
npm run dev -- --host 127.0.0.1
```

Open the localhost URL printed by Vite. The chat and avatar appear side by side
on wider screens and stack on smaller screens. Submit messages in the chat
panel; follow-up turns include the in-memory browser conversation. **New
conversation** clears the current messages. Reloading the page also clears
them; nothing is persisted to disk.

If Ollama is stopped or Qwen3 4B is unavailable, the UI shows the backend error
and keeps the message visible so you can resend it after fixing the local runtime.

For an assistant response, choose **Generate audio** to synthesize speech
locally. When it is ready, use **Play audio**, **Pause audio**, **Resume audio**
and **Stop audio**. Only one response can play at a time; sending another chat
message or starting a new conversation stops current speech. If Kokoro or its
weights are unavailable, the UI displays an error while leaving the text reply
available. TTS is optional; the chat works without installing the `tts` extra.

## Tests

Backend tests mock Ollama and Kokoro responses and do not require running AI
models:

```powershell
cd backend
.\.venv\Scripts\Activate.ps1
python -m pytest -q
```

Frontend tests mock chat and TTS HTTP responses and do not call Ollama or Kokoro:

```powershell
cd frontend
npm test
npm run build
```

## Hardware feasibility checks

The existing standalone checks remain available. The `tts` extra is sufficient
for the app's local TTS. Install the separate feasibility extra only when
running all feasibility checks, including STT:

```powershell
cd backend
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[feasibility]"
python scripts\check_llm.py
python scripts\check_tts.py
python scripts\check_stt.py artifacts\feasibility\kokoro-check.wav
```

Speech checks run on CPU. The feasibility script writes test WAV files under
`backend\artifacts\feasibility`; no microphone recording or uploaded voice data
is involved.
